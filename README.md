# SanTa

> 내 체력에 맞는 산과 등산 코스를 찾아보는 웹 서비스

등산을 시작할 때 어떤 코스를 골라야 할지 고민하는 사람들을 위해 만들었습니다. 산림청 공공데이터를 가공해 코스의 거리, 소요 시간, 난이도를 보여주고, 산행 후에는 후기와 내 등산 기록을 남길 수 있습니다.

## 주요 기능

| 기능            | 내용                                                                       |
| --------------- | -------------------------------------------------------------------------- |
| 코스 추천       | 쉬운 코스 중 총 소요 시간이 짧은 3개 코스 추천                             |
| 검색            | 산 이름·코스 이름 검색, 메인 검색창 자동완성                               |
| 필터·정렬       | 난이도, 거리, 소요 시간, 지역, 통제·폐쇄 여부 필터와 거리·시간순 정렬      |
| 코스 상세       | 거리, 난이도, 산 높이, 상행·하행 시간, 지형, 위험구간 정보 표시            |
| 지도            | 카카오맵에서 산 위치 확인, 위치 후보 선택, 외부 길찾기 연결                |
| 회원가입·로그인 | Supabase Auth를 이용한 이메일·비밀번호 인증                                |
| 후기            | 코스별 후기 조회, 로그인 후 작성, 본인 후기 삭제                           |
| 내 등산 기록    | 후기 작성 시 코스 기록 추가, 기록 목록·누적 거리·예상 시간 확인, 기록 삭제 |

검색과 코스 정보, 후기는 로그인 없이 볼 수 있습니다. 후기 작성과 내 등산 기록은 로그인이 필요합니다.

## 기술 스택

- **화면:** HTML, CSS, Vanilla JavaScript
- **데이터 조회:** Fetch API, JSON
- **지도:** Kakao Maps JavaScript API
- **인증·DB:** Supabase Auth, PostgreSQL, RLS
- **개발 도구:** Node.js 내장 모듈을 이용한 로컬 서버와 데이터 전처리

## 실행 방법

### 1. 프로젝트 준비

Node.js가 설치된 환경에서 저장소를 내려받습니다.

```bash
git clone https://github.com/lsy090601/SanTa.git
cd SanTa
```

이미 프로젝트가 있다면 해당 폴더에서 터미널을 열면 됩니다. 별도 패키지 설치나 빌드 없이 실행하는 정적 웹 프로젝트입니다.

### 2. 설정값 입력

[.env.example](.env.example)은 필요한 설정 이름만 적어둔 제출용 템플릿입니다. 값은 비워두었습니다.

```dotenv
KAKAO_JAVASCRIPT_KEY=
SUPABASE_URL=
SUPABASE_PUBLISHABLE_KEY=
```

**현재 웹 페이지는 `.env`를 자동으로 읽지 않고 [config.js](config.js)를 불러옵니다.** 위 이름에 해당하는 실제 값을 아래 항목에 직접 입력해야 합니다. `.env` 파일을 만들거나 배포 서비스에 환경 변수만 등록해도 자동으로 반영되지는 않습니다.

| 템플릿 이름                | `config.js` 항목         | 필요한 값                        |
| -------------------------- | ------------------------ | -------------------------------- |
| `KAKAO_JAVASCRIPT_KEY`     | `kakaoJavaScriptKey`     | 카카오 JavaScript 키             |
| `SUPABASE_URL`             | `supabaseUrl`            | Supabase 프로젝트 URL            |
| `SUPABASE_PUBLISHABLE_KEY` | `supabasePublishableKey` | 같은 Supabase 프로젝트의 공개 키 |

```javascript
window.SANTA_CONFIG = {
  kakaoJavaScriptKey: "카카오 JavaScript 키",
  supabaseUrl: "https://프로젝트ID.supabase.co",
  supabasePublishableKey: "Supabase Publishable key",
  reviewsTable: "reviews_v2",
};
```

`reviewsTable`은 `reviews_v2`로 유지합니다. 브라우저에서 사용하는 설정이므로 Supabase secret 키, `service_role` 키, DB 비밀번호는 넣지 않습니다. ([Supabase 키 안내](https://supabase.com/docs/guides/getting-started/api-keys))

카카오 개발자 사이트에서 JavaScript 키의 SDK 도메인에 `http://localhost:8080`을 등록하고, 카카오맵 사용 설정을 확인합니다. 배포 시에는 배포 주소도 등록해야 합니다. ([Kakao Maps 설정 안내](https://apis.map.kakao.com/web/guide/))

### 3. Supabase 설정

새 Supabase 프로젝트에서 실행하는 경우 다음 설정이 필요합니다. 이미 팀 프로젝트에 설정되어 있다면 적용 여부를 먼저 확인합니다.

1. 이메일·비밀번호 회원가입과 로그인을 사용할 수 있도록 Authentication을 설정합니다.
2. SQL Editor에서 [reviews_auth_migration.sql](reviews_auth_migration.sql)을 실행해 `reviews_v2` 테이블과 접근 권한을 만듭니다. 기존 DB를 사용한다면 파일 상단의 조회 SQL로 테이블과 정책을 먼저 확인합니다.
3. [visits_table.sql](visits_table.sql)을 실행해 `visits` 테이블과 접근 권한을 만듭니다.
4. 이메일 인증을 사용할 경우 Authentication의 URL 설정에서 인증 후 돌아갈 사이트 주소를 확인합니다. 로컬 전용 프로젝트라면 Site URL을 `http://localhost:8080`으로 설정합니다. 이미 배포 중인 프로젝트는 기존 배포 주소를 유지하고 인증 후 해당 사이트에서 로그인할 수 있습니다.

현재 회원가입은 Supabase Auth를 사용합니다. `reviews_table.sql`은 이전 회원·후기 구조를 위한 파일이므로 새 설치에서는 실행하지 않습니다. 기존 `public.users` 계정과 `reviews` 후기는 새 인증·후기 구조로 자동 이전되지 않습니다. 마이그레이션은 기존 후기의 쓰기를 막고, 기존 데이터는 남겨둡니다.

### 4. 로컬 서버 실행

프로젝트 루트에서 실행합니다.

```bash
node scripts/serve.cjs
```

브라우저에서 [http://localhost:8080](http://localhost:8080)에 접속하면 메인 페이지로 이동합니다. 종료할 때는 터미널에서 `Ctrl+C`를 누릅니다.

- HTML 파일을 더블클릭하는 `file://` 방식은 JSON 조회가 제한될 수 있으므로 로컬 서버를 사용합니다.
- 기본 포트는 `8080`입니다. 이미 SanTa 서버가 실행 중이면 기존 주소로 접속하면 됩니다.
- 지도, 로그인, 후기 기능은 외부 API를 사용하므로 인터넷 연결과 해당 서비스 설정이 필요합니다.

## 테스트 계정 가이드

공용 계정 대신 **회원가입으로 테스트 계정을 만들어 사용합니다.**

### 계정 만들기

1. [회원가입 페이지](http://localhost:8080/signIn.html)에 접속합니다.
2. 메일을 받을 수 있는 이메일, 닉네임, 비밀번호, 비밀번호 확인을 입력합니다.
3. Supabase에서 이메일 인증을 사용 중이면 받은 메일의 인증 링크를 누릅니다.
4. [로그인 페이지](http://localhost:8080/logIn.html)에서 가입한 이메일과 비밀번호로 로그인합니다.

비밀번호는 연결된 Supabase 프로젝트의 정책에 맞게 입력합니다. 이메일 인증 여부도 프로젝트 설정에 따릅니다. ([이메일·비밀번호 인증 안내](https://supabase.com/docs/guides/auth/passwords))

### 기능 확인 순서

| 순서 | 테스트 방법                                  | 확인할 내용                                    |
| ---- | -------------------------------------------- | ---------------------------------------------- |
| 1    | 비로그인 상태에서 메인 접속                  | 추천 코스 3개 표시                             |
| 2    | 산 이름이나 코스를 검색                      | 검색 결과와 상세 페이지 연결                   |
| 3    | 난이도·거리·시간·지역을 선택하고 `필터 적용` | 선택한 조건에 맞는 결과 표시                   |
| 4    | 코스 상세에서 지도 후보 선택                 | 산 위치 표시와 카카오맵 길찾기 연결            |
| 5    | 로그인 후 상세 페이지에서 후기 작성          | 후기 목록에 작성한 내용 표시                   |
| 6    | 새로고침 후 후기 확인                        | DB에 저장한 후기 유지                          |
| 7    | 상단 `내 기록` 선택                          | 작성한 코스와 누적 거리·예상 시간 표시         |
| 8    | 같은 날 같은 코스에 후기 추가                | 후기는 추가되고 등산 기록은 중복 추가되지 않음 |
| 9    | 본인 후기와 등산 기록 삭제                   | 각각의 목록에서 삭제됨                         |
| 10   | 로그아웃 후 `내 기록` 접속                   | 로그인 페이지로 이동                           |

예시 코스는 [가련산 덕진동1가구간](http://localhost:8080/detail.html?id=PMNTN_00001)에서 확인할 수 있습니다.

다른 이메일로 계정 B를 만들면 계정 A의 후기는 조회할 수 있지만 삭제 버튼은 보이지 않아야 합니다. 내 기록에는 각 계정의 기록만 표시되어야 합니다. 서버 권한까지 확인할 때는 B 계정으로 A의 후기 삭제 요청을 보내도 실제 행이 삭제되지 않는지 확인합니다.

후기와 등산 기록은 별도로 관리합니다. 후기만 삭제해도 등산 기록은 남고, 등산 기록만 삭제해도 후기는 남습니다. 기록의 날짜는 DB의 날짜 기준이며, 누적 시간은 실제 측정 시간이 아닌 코스 예상 시간의 합계입니다.

## 데이터와 난이도 기준

산림청 산 정보와 등산로 속성을 가공한 JSON을 저장소에 포함했습니다. 서비스 실행 중 공공데이터 API를 매번 호출하지 않습니다.

| 파일                                               | 용도                                            |
| -------------------------------------------------- | ----------------------------------------------- |
| `data/courses.json`                                | 검색·추천·상세에서 사용하는 코스 데이터 7,645개 |
| `data/mountains.json`                              | 산 이름·높이·주소를 담은 산 정보 4,704개        |
| `data/등산로_속성.json`                            | 코스 전처리에 사용하는 등산로 구간 속성         |
| `data/산정보_목록.json`, `data/산이미지_정보.json` | 산 높이·지역·이미지 연결에 사용하는 자료        |
| `data/산림관광_통합데이터.json`                    | 산 정보 목록 생성에 사용하는 원본 자료          |

메인과 검색에서는 산 높이가 있고, 거리가 1km 이상이며, 총 소요 시간이 0보다 큰 코스만 사용합니다.

난이도는 [preprocess/build_courses.js](preprocess/build_courses.js)에서 다음 기준으로 계산합니다.

```text
난이도 점수 = 거리(km) + 상행 소요 시간(분) / 20
```

| 점수           | 데이터의 난이도 | 메인·검색 화면 표시 |
| -------------- | --------------- | ------------------- |
| 4 미만         | 초심자          | 쉬움                |
| 4 이상, 9 미만 | 중급자          | 중간                |
| 9 이상         | 고수            | 어려움              |

같은 산 코드와 코스 이름을 가진 구간의 거리·시간을 합산하고, 거리·시간이 0 이하인 데이터와 거리 30km 초과 또는 총 시간 720분 초과인 데이터를 제외합니다. 표고차는 현재 계산에 사용하지 않습니다.

가공된 파일이 포함되어 있어 일반 실행에는 전처리가 필요하지 않습니다. 데이터를 다시 만들 때만 프로젝트 루트에서 실행합니다.

```bash
node preprocess/build_courses.js
node scripts/prepare-mountains.cjs
```

코스 ID는 순번으로 생성되므로 원본 데이터가 바뀌면 ID도 바뀔 수 있습니다. 기존 후기·등산 기록이 있는 경우 연결된 ID를 확인한 뒤 데이터를 교체해야 합니다.

## 데이터 저장 방식

| 데이터                | 저장 위치                                          |
| --------------------- | -------------------------------------------------- |
| 회원 계정·인증        | Supabase Auth                                      |
| 후기                  | Supabase `reviews_v2` 테이블                       |
| 내 등산 기록          | Supabase `visits` 테이블                           |
| 로그인 세션           | Supabase 클라이언트가 브라우저 localStorage에 저장 |
| 로그인 후 돌아갈 주소 | 브라우저 sessionStorage                            |
| 산·코스 정보          | 저장소의 JSON 파일                                 |

후기와 등산 기록은 브라우저 저장소에 보관하지 않습니다. 로그인 여부는 `auth.getUser()`로 확인하고, DB의 RLS 정책으로 작성자와 기록 소유자의 권한을 구분합니다. 로그인 세션 저장은 [Supabase 기본 설정](https://supabase.com/docs/reference/javascript/auth)을 사용합니다.

## 프로젝트 구조

```text
SanTa/
├── fronted/
│   ├── index.html             # 메인·추천
│   ├── search.html            # 검색·필터
│   ├── js/                    # 메인·검색·공통 데이터 처리
│   ├── css/
│   └── images/
├── detail.html                # 코스 상세·지도·후기
├── logIn.html                 # 로그인
├── signIn.html                # 회원가입
├── mypage.html                # 내 등산 기록
├── js/
│   ├── auth.js                # Supabase 연결·로그인 확인
│   ├── header.js              # 공통 헤더·로그아웃
│   └── course-map.js          # 지도·위치 검색·길찾기
├── data/                      # 원본·가공 JSON
├── assets/                    # 공통 아이콘
├── preprocess/build_courses.js
├── scripts/
│   ├── serve.cjs              # 로컬 서버
│   └── prepare-mountains.cjs  # 산 정보 가공
├── config.js                  # 브라우저에서 읽는 설정
├── .env.example               # 설정 이름 템플릿
├── reviews_auth_migration.sql # 현재 후기 테이블·RLS
├── visits_table.sql           # 등산 기록 테이블·RLS
├── vercel.json                # 루트 주소를 메인으로 연결
└── README.md
```

`fronted`는 현재 저장소의 폴더명입니다. `supabaseClient.ts`는 현재 HTML에서 사용하지 않으며, 실행 시 연결 설정은 `config.js`와 `js/auth.js`를 기준으로 합니다.

## 실행 중 문제가 생기면

| 증상                             | 확인할 내용                                                         |
| -------------------------------- | ------------------------------------------------------------------- |
| JSON이나 화면을 불러오지 못함    | 프로젝트 루트에서 서버를 실행했는지, `file://`로 열지 않았는지 확인 |
| 지도가 표시되지 않음             | JavaScript 키, SDK 도메인의 주소·포트, 카카오맵 사용 설정 확인      |
| 회원가입 후 로그인 실패          | 이메일 인증 완료 여부, 입력한 비밀번호, Supabase 연결 설정 확인     |
| 후기를 불러오거나 저장하지 못함  | `reviews_v2` 테이블, `reviewsTable` 값, 로그인 상태와 RLS 확인      |
| 후기는 저장되지만 내 기록에 없음 | `visits_table.sql` 적용 여부와 `visits` 테이블 권한 확인            |
| 설정을 바꿔도 반영되지 않음      | `.env`가 아닌 `config.js`를 수정했는지 확인하고 새로고침            |
